Background

My journey into cloud engineering followed a deliberate, compounding progression. I began in Medical Laboratory Science, a field where clinical precision is non-negotiable and a single missed control invalidates a patient's diagnostic result. That lab-tested discipline naturally drew me into cybersecurity, where I learned to think like an adversary, audit system vulnerabilities, and dismantle vector pathways. Today, that exact chain of experience forms my core framework for cloud engineering. In my builds, an overly permissive IAM policy, an exposed credential, or a manual configuration step is treated as a critical breach risk, forcing me to approach cloud architecture with the diagnostic rigor of a lab scientist and the defensive mindset of a security engineer.

Building on that security foundation, I completed the AWS Cloud Computing and AI programme at Azubi Africa, where I served as Project Coordinator for Team Tomcat. Across the three capstone projects in our cohort, our team took the top score in two of the challenges and achieved the highest cumulative score overall. Managing our engineering workflow meant doing far more than writing cloud templates; I coordinated architectural decisions, managed repository structures, and enforced strict deployment standards across our builds. Together, we designed, deployed, and maintained production-grade, zero-idle serverless platforms equipped with real domain routing, custom API integrations, and event-driven backends built to handle live user traffic.

My engineering capabilities bridge cloud architecture and high-performance software design. Beyond cloud-native architecture, I write custom C# tools for quantitative trading and design event-driven portfolio simulation engines. Working on multi-asset financial tools forces you to confront hard engineering limits around execution latency, concurrency, memory management, and state synchronization. This dual focus gives me a unique edge in cloud operations, as I design infrastructure with a deep, practical understanding of how code actually executes at the application layer.

I view zero-trust security and complete CI/CD automation as non-negotiable entry requirements for any production environment. If a deployment pipeline relies on long-lived AWS access keys, requires manual server configuration, or lacks dynamic scaling, it is simply incomplete. From OIDC-based federated deployment pipelines to token-authorized microservices, I build low-maintenance, cost-optimized cloud solutions that scale seamlessly while keeping security locked down at every boundary and operating costs locked to actual demand. I am actively seeking my next Cloud DevOps Engineering role, where I can bring this combination of technical leadership, diagnostic precision, and security-first engineering to a forward-thinking team.
